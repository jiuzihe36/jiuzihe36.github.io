# 为什么我偏爱零依赖的静态站点

每次开新项目，我都会先问自己一个问题：**这件事真的需要引入依赖吗？**

## 依赖的隐性成本

一个 npm 包背后，往往牵出一整棵依赖树。它们带来：

- 安装时间
- 安全审计负担
- 版本漂移导致的「在我机器上能跑」

对于个人博客这种需求稳定的场景，自己写一个 ~200 行的生成器，反而更省心。

## 一个最小可用的 Markdown 解析器

其实核心逻辑并不复杂：

1. 按空行切分块
2. 判断块类型（标题 / 列表 / 引用 / 代码块 / 段落）
3. 行内替换（加粗、链接、代码）

```js
text.replace(/\*\*([^*]+)\*\*/g, '<strong>$1</strong>');
```

## 取舍

零依赖不是银弹。如果你的站点需要评论、搜索、国际化，那引入成熟方案更划算。**关键是想清楚边界。**

我的原则：先把功能做小，确认它长期不变，再决定要不要自己写。
